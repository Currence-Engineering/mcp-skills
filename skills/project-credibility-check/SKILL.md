# Project Credibility Check

Separate announcements from projects that are coming. Requires the Currence MCP with Data Centers & Power access.

## Steps
1. Identify the scope: a project, a developer, or a region.
2. Project check: read the Currence credibility score factor by factor (status, scale, developer tier, financing signals, power supply, powering plan, time to power, offtake). Name the weakest factor.
3. Check the evidence behind it: contracts and offtakes, financing and deals, and market events from the last 12 months.
4. Developer check: pull the developer's projects and compare announced with delivered. Report delivery rate, the status mix (announced, construction, delayed, canceled, operational) and recent milestone changes.
5. Region check: list projects in the region with their credibility scores, powering model (grid, on-site, hybrid), utility, and any large load tariff or moratorium that applies. Say who else is competing for power.
6. For credible capacity forecasts, read the Currence data center forecast research before touching project records, then weight capacity by credibility.
7. Say what would move the score: the specific missing piece to watch, such as a signed offtake or an announced power supply.
8. Link every project and developer to the Currence platform.

## Limits
- No utility service territory data yet, so grid headroom and time to energization by utility are not available.
- Regional time to power is only available inside each project's credibility reasoning, not as a clean comparable field.
- No land use or parcel data.
- Project delay reasons are not stored as a field. Use events to explain delays where you can.

## Format
Lead with a verdict: credible, mixed or unproven, and the single biggest reason. Then the evidence, then what would move the score.
